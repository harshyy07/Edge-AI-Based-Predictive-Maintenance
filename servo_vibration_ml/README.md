# Servo vibration ML pipeline

This directory is an isolated servo-specific experiment. The industrial motor pipeline, its `model.h`, and all source datasets remain unmodified.

## Run

From this directory, using an environment with `numpy`, `pandas`, `scikit-learn`, `matplotlib`, and `joblib`:

```powershell
python train.py
```

Labeled raw MPU6050 CSVs in `data/servo_phase1_*.csv` are discovered automatically. Files can also be specified with `--csv path1.csv path2.csv`. Expected acceleration columns are `ax_g, ay_g, az_g`; label can be `label`, `class`, `condition`, or `fault`. `window_id` marks sample boundaries. Optional `trial_id` or `recording_id` identifies validation groups; otherwise each source file is one held-out group. Capture independent physical trials to separate files or label them with a trial identifier. Labels must remain constant within a 200-row window. Only complete windows are used.

The supplied pasted experiment text is real servo measurement data containing aggregate RMS/peak readings across `DETACHED`, three stationary angles, and `MOVING`. Process its readable fields with `python summarize_real.py "path\to\Pasted text.txt"`. It is preserved as a separate real summary dataset and is not passed to the raw-signal classifier because aggregate values cannot reconstruct the three-axis 200-sample windows or the 12 features.

## Signal and feature contract

The synthetic baseline uses 200 Hz sampling, one second (200 samples) per window, acceleration in g, and patterns below 100 Hz. Six labels are modeled: `NORMAL`, `HIGH_FRICTION`, `MOUNTING_LOOSENESS`, `ABNORMAL_VIBRATION`, `IRREGULAR_MOVEMENT`, and `STOP`. Synthetic rows carry `provenance=synthetic`; supplied CSVs carry `provenance=real_servo_csv`.

The 12 features are per-axis mean, standard deviation, RMS, and absolute peak, ordered as X then Y then Z. `model.h` uses this same feature order and supplies `servo_rf_predict(features)` plus the class-label array. The header is generated by training and is separate from the industrial model header. Compile it in the ESP32 firmware project before integration; this task does not upload firmware.

## Interpretation

With no servo CSVs present, reported scores measure separation of randomized synthetic patterns only. They are not evidence of real servo fault detection. Even when real files are later added, a mixed grouped score is only exploratory unless the test set contains independent, physically verified servo trials for every reported fault. MaFaulDA and CWRU are not included: they describe different rotating machinery and are unsuitable as direct servo labels.

See `REPORT.md` and `results/metrics.json` for run-specific counts and metrics.
